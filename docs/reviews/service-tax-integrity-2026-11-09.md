## Remaining financial limitations and audit questions

1. **Existing taxable flag gap:** TypeScript booking calculations and public SQL do not use `services.taxable`. With a positive business default, taxable=false is not reliably exempt. Zero service override means inherit and cannot represent explicit zero-rated service override. This patch preserves existing behavior and zero-default business support; it does not falsely claim exemption support. A global exemption/zero-rating contract and coordinated writers need a separately approved scope (including SQL if required). This is a tax-readiness blocker, not an accepted safe deferral.
2. **No immutable rate/name/mode snapshot:** amount preservation is safe, but generic “Tax” is not proof of jurisdictional invoice/receipt disclosure compliance. Do not reuse an appointment email as a formal tax invoice without review. Schema changes are outside authority. Receipt/invoice metadata provenance and regional requirements need audit before release.
3. **Catalog concurrency:** the session path re-reads on the server but does not lock catalog rows atomically with insertion; an operator can change policy between those operations. This patch prevents inconsistent client stamps against the server read, not all concurrent catalog races. Existing durable snapshot semantics are untouched. Separate decision if an atomic guarantee is required.
4. **Default selection/overrides:** missing default falls back to first active rate by name; no catalog means zero. Custom rate inherits default inclusive mode and pricing helpers may borrow the default's label. Multiple defaults and cross-region/multi-component tax rules are not solved here. Existing staff-specific price display and submitted catalog price can differ; this patch does not invent a staff-price contract.
5. **Data versus code:** a legitimate stored 13-bps override still yields 15 cents. Code cannot know the operator intended 13%. The specific configuration correction is a separate approved action; historical appointments remain untouched.
6. **Coverage boundary:** synthetic mocks do not prove deployed RLS, SQL/catalog-lock behavior, physical iPhone/iPad usability, actual operator acceptance, or Production tax legality. No hosted financial test or CI rerun occurred. Local Node 26.7.0 differs from CI Node 22. Financial modules/SQL/migrations/payment ledger are not rewritten.
